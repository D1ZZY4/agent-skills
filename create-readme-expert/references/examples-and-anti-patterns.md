# Examples and Anti-Patterns

Worked README examples and common pitfalls.

## Good README traits

- First code block is copy-paste runnable.
- Each section answers a concrete question.
- Examples use realistic but simplified data.
- Known limitations are stated plainly.

## Common anti-patterns

- README that reads like a changelog or release notes.
- README that only restates the project name and GitHub link.
- README examples that depend on services, keys, or environments not described in the README.
- README that claims features without showing how to use them.
- README that mixes multiple unrelated tutorials into one page.

## Example opening

Bad: "This project is awesome and does amazing things."

Better: "A minimal tool for generating README files from project metadata. Install it, point it at a project, and get a README draft."
